# Turkish Lyrics Generation with a GRU

Coursework project, 2023.

## Problem

Generate Turkish song lyrics with a character/word-level language model, trained on a
corpus of Turkish song and poem lyrics that I collected myself by scraping.

## Method

A GRU-based language model built with Keras: an `Embedding` layer feeding stacked GRU
units, trained with Adam to predict the next token. Text is generated by sampling from
the model autoregressively, so it can produce lyrics of arbitrary length.

The corpus was scraped in two parts — song lyrics from `sarkisozlerihd.com` and poems
from `siir.sitesi.web.tr` — using `requests` + `BeautifulSoup`, then written out to
spreadsheets. It came to roughly 94k lines of lyrics.

> The notebook is named `song_gpt.ipynb` for historical reasons; the model in it is a
> GRU, not a GPT-style transformer.

## Data

The scraped `.xlsx` corpus is **not** included in this repository — it is third-party
lyrics text, and republishing it is not mine to do. What is included is the scraping
code that produced it, under `scraping-project/`:

- `scraping-project/lyrics/` — `lyrics.py`, `main.py`: walk per-artist index pages,
  follow each song link, extract the lyrics body, append rows to a dataframe.
- `scraping-project/poems/` — `poems.py`, `poetry_lyrics.py`: same idea over paginated
  poem listings.

Running those scripts regenerates an equivalent corpus. Expect the selectors to need
fixing — the markup of both sites has almost certainly changed since 2023.

## Libraries

`tensorflow` / `keras`, `numpy`, `pandas`, `scikit-learn`, `matplotlib`,
`requests`, `beautifulsoup4`, `openpyxl`

## Result

The model produces fluent-looking Turkish with correct syllable rhythm, but the output
is mostly not meaningful — words drift and lines do not hold a subject. The corpus is
too small to saturate the model, which is the main limitation.
